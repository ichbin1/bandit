# Веб-интерфейс (`bandit.web`)

Локальный конструктор экспериментов: собрать «среда × агенты × политики»,
посмотреть объём работы, запустить счёт и изучить метрики — без правки
Python-кода. Сервер слушает только `127.0.0.1` по умолчанию: это инструмент
для своей машины, а не многопользовательский сервис.

## Запуск

```powershell
pip install -e .[ui]            # fastapi + uvicorn
python -m bandit.cli ui         # http://127.0.0.1:8000/ , браузер откроется сам
python -m bandit.cli ui --port 8100 --no-browser
python -m bandit.cli ui --reload            # автоперезагрузка при правке кода
python -m bandit.web --port 8100            # то же, без остальных команд CLI
```

Каталог результатов по умолчанию — `results/` в корне репозитория; его можно
переопределить переменной окружения `BANDIT_RESULTS_DIR`:

```powershell
$env:BANDIT_RESULTS_DIR = "D:\runs"     # PowerShell
python -m bandit.cli ui
```

## Что можно настроить

| блок | содержимое |
| --- | --- |
| Среда | `layered`, `pyramid`, `bernoulli`, `gaussian`; поля выводятся из конструктора среды (`inspect.signature`), поэтому новый параметр появляется в UI сам |
| Пресеты | «По умолчанию» (= параметры из `configs.py`) и режимы H6: `base`, `abundant`, `noisy`, `noisy_fed`, `starved`, `flood` |
| Агенты | все ключи `configs.AGENTS` (8) с реальными значениями параметров: ε, `epsilon_decay`, `c`, `alpha`, `initial_value` |
| Политики | все ключи `configs.POLICIES` (11), включая оракулов; у `learned`/`learned_slow` — `c` и `window` |
| Прогон | название, число прогонов на конфиг, шагов, сид, `--jobs`, графики, «добавить оракула» |

Матрица строится как декартово произведение выбранных агентов и политик;
«добавить оракула» добавляет конфиг `ui-<среда>-oracle-full_cycle` с
`expose_oracle=True` — он нужен для метрики КПД. Политика `oracle_*`,
выбранная вручную, тоже автоматически получает `expose_oracle`.

`arm_mean_sampler` (callable) намеренно не выносится в UI: он задаётся только
из кода, и сервер честно пишет это в подсказке под полями среды.

## Проверка и запуск

* **Проверить** (`POST /api/validate`) — прогон по 32 шага на каждый конфиг.
  Это настоящий счёт, поэтому ошибки приходят из конструктора среды
  («means должно содержать 3 значений…»), а не из самодельных проверок.
* **Запустить** (`POST /api/jobs`) — сначала та же проверка, затем задание
  становится в очередь. Очередь последовательная (один воркер), а параллелизм
  внутри задания задаётся `--jobs`: так прогресс предсказуем, а CPU не делится
  между заданиями незаметно для пользователя.
* **Остановить** (`POST /api/jobs/{id}/cancel`) — `terminate` дочернего
  процесса: счёт действительно прекращается.

Задание — обычный CLI-прогон в отдельном процессе:

```
python -m bandit.cli run \
    --config-file results/<id>/configs.json \
    --runs N --seed S --jobs K --out results/<id> [--no-plots]
```

Спецификация (`spec.json`) и собранные конфиги (`configs.json`) лежат в
каталоге прогона. Поэтому любой прогон из браузера воспроизводится из
терминала одной командой (она же пишется в `manifest.json` и в лог задания).

## Результаты

Вкладка «Результаты» не требует, чтобы прогон был запущен из UI: список
строится по `results/*/manifest.json`, поэтому старые прогоны и прогоны из
CLI видны сразу и переживают перезапуск сервера.

* таблица метрик: `final_points`, `cumulative_arm_regret`, `optimal_arm_rate`,
  `points_per_pull`, `efficiency`, `steps_to_90pct` в форме mean ± SEM
  (полный набор — в `metrics.csv`);
* графики `dashboard.png` и `final_points.png` (если прогон их построил);
* вердикты H1–H6 из `report.json`; кнопка «Построить отчёт» вызывает тот же
  `bandit.cli report`, что и терминал, и перечитывает результат.

## Оценка времени

Сводка показывает ожидаемое время по замеру ≈**5 тыс. шагов/с на один процесс**
(прогоны `adv-s1`, `adv-s2`, `_h6_10`). Формула:
`шаги × прогоны × конфиги / 5000`. Оценка линейная и не учитывает `--jobs`,
поэтому при `--jobs 2` реальное время обычно меньше, а на слабой машине —
больше.

## API

Все ответы — JSON (`/api/runs/{id}/file/{name}` — файл). Модели описаны в
`bandit/web/models.py` с `extra="forbid"`: опечатка в имени поля даёт 422 с
путём до него, а не тихо игнорируется.

| метод | путь | назначение |
| --- | --- | --- |
| GET | `/api/health` | версия, каталог результатов, активные задания |
| GET | `/api/schema` | среды/агенты/политики, defaults, наборы, описания метрик |
| POST | `/api/preview` | конфиги, эпизоды, шаги, оценка времени |
| POST | `/api/validate` | прогон по 32 шага, список ошибок |
| POST | `/api/jobs` | поставить задание в очередь |
| GET | `/api/jobs` | все задания (новые сверху) |
| GET | `/api/jobs/{id}` | состояние, прогресс, хвост лога |
| POST | `/api/jobs/{id}/cancel` | остановить задание |
| GET | `/api/runs` | список прогонов из `results/*/manifest.json` |
| GET | `/api/runs/{id}` | таблица метрик + вердикты |
| POST | `/api/runs/{id}/report` | пересчитать `report.md`/`report.json` |
| GET | `/api/runs/{id}/file/{name}` | `metrics.csv`, `report.md`, `report.json`, `dashboard.png`, … |

Отдаются только файлы из белого списка (`FILES` в `bandit/web/app.py`), а
`run_id` проверяется регулярным выражением — выйти за каталог результатов
через путь нельзя (`_run_dir`). Статика монтируется на `/` последней, чтобы не
перехватывать `/api/*`.

## Ограничения

* Нет аутентификации и доступа по сети: сервер рассчитан на `127.0.0.1`.
  Если открыть его наружу, любой в браузере сможет запускать прогоны.
* Очередь заданий живёт в памяти процесса: перезапуск сервера теряет список
  заданий (но не сами прогоны — они уже в `results/`).
* Спецификация не покрывает `scripts/advantage_sweep.py` (оси S0/S1/S2/S6) и
  `scripts/advantage_report.py`: это отдельный исследовательский слой. UI
  строит конфиги только из реестра `configs.py`.
* Прогресс задания считается по числу готовых `*.npz`: внутри одного длинного
  конфига индикатор стоит на месте, зато в логе видно каждый прогон.

## Тесты

```powershell
pytest tests/test_web_schema.py tests/test_web_app.py -q
```

`tests/test_web_schema.py` проверяет поля конструктора и чистую сборку
конфигов, `tests/test_web_app.py` — HTTP-слой через `TestClient` (включая
настоящий прогон 3 конфигов × 1 прогон, отмену задания и сборку отчёта).
